## A process failure worth recording first

A sub-agent told explicitly not to edit anything wrote temporary probe tests
into three Rust files. I then staged with `git add -A` and committed them
alongside unrelated work (`daa2722`), reverted in `fdcd0f9`.

Two things follow, and the second is the useful one:

1. **Stage named paths, not `-A`,** while any sub-agent is running.
2. **The repo's own guard caught it.**
   `no_adapter_source_opens_foreign_paths_for_writing` (`adapters/mod.rs:751`)
   greps every file under `adapters/` for write markers and failed
   immediately, because the probe tests wrote sample files. That test exists

   intrusion nobody anticipated. Recorded because it is the strongest
   evidence yet that this kind of structural guard earns its place.

## The import adapters -- never audited before this pass

`claude_code.rs` and `vscode_copilot.rs` read conversations out of other AI
tools. The vision is strict here: import, continue-here and continue-
externally "must never be presented as equivalent", and imported output
"stays visibly attributed to its original client".

**What was verified sound** (checked mechanically, not by reading comments):

- **Genuinely read-only.** Neither file constructs `OpenOptions`,
  `File::create`, or any `fs::write/remove/rename/copy`. All foreign I/O goes
  through a read-only open. No handle is held across an operation; no locking.
- **Continuation honesty is correct.** Claude Code returns `OpenOnly` with a
  comment explaining that `--resume` exists but is not wired, declining to
  claim a capability it lacks; VS Code returns `Unsupported` and pins it with
  a test. Neither ever returns `ResumeSession`.
- **The VS Code workspace hash is never guessed from** -- an absent sidecar
  yields `None` rather than an invented path.
- **Unrecognised records are preserved**, not dropped, and both files test it.

### Fixed: a conversation was filed under where it ended (`ef8a0d3`)

`cwd` is recorded per line, and `parsed.cwd.clone().or(cwd)` is **last-wins**.
A conversation that moves directories -- into a submodule, a worktree, a
sibling repo, all ordinary -- was attributed to whichever directory its last
record happened to name.

That is worse than not knowing, and specifically defeats a principle
`reconcile.rs:57-59` states outright: *"a wrong guess (matching a session to
the wrong repo) is worse than an honest `Unresolved`."* Reconcile matches
exactly and refuses to guess -- so a confidently wrong path does not fail to
resolve, it resolves to the **wrong project**. The safeguard was defeated
upstream, before reconcile ever saw the value.

The same line fixed `updated_at`, which took the last record's timestamp
rather than the newest. Records are not guaranteed monotonic (session
management appends its own lines; a resumed conversation interleaves), so a
conversation could display a "last updated" older than messages plainly
visible inside it, and sort wrongly in a newest-first list.

### Fixed: workspace paths were half-decoded (`f106e4c`)

`file_uri_to_path` replaced only `%3A`. Two consequences, both silent:

- A folder with a **space** -- `My Documents`, and every folder like it --
  arrived as `my%20project` and could never match an open project. The person
  was told GitWyrm could not find a folder they were looking at.
- `strip_prefix("file:///")` ate the **leading slash** of a POSIX path, so
  every macOS and Linux workspace resolved to a relative path matching
  nothing.

Now properly percent-decoded, with a Windows-drive check so `/c:/x` loses its
URI slash while `/home/x` keeps its root. A literal `%` in a folder name
survives unchanged -- mangling it would be the same class of mistake.

### Reported and not acted on

Four further findings arrived that I did not treat as actionable this pass,
recorded so the next reader can judge rather than re-derive:

- **Duplicate session ids across workspaces** (`vscode_copilot.rs:225`).
  `read_session` re-derives a path by searching instead of using the one
  `list_sessions` already knew. Real, and the agent demonstrated it -- but the
  fix is a signature change through the adapter trait, which is a larger
  change than the evidence (requires a copied `workspaceStorage`) justifies
  ahead of the items above.
- **A non-UTF-8 byte discards a whole transcript** while the listing path
  skips the bad line. The asymmetry is real; the fix belongs with the shared
  `read_foreign_file_to_string`, which serves adapters this pass did not audit.
- **VS Code's message count is `requests.len() * 2`**, a guess presented as a
  count, while the read path produces 1-3 per turn. Sibling adapters count
  properly.
- **Missing timestamps render as a real 1970 date.** The "unknown stays
  unknown" rule applies; `Option` was available and unused.

## F7 -- settled, and not the way it was framed (`24a9fac`, `daa2722`)

The competitive audit filed F7 as "the first-chat experience asks the same
setup questions twice". Two agents argued cutting the landing down versus
keeping its teaching role and removing the duplication instead.

Neither won on its own terms, because the argument surfaced something that is
not a matter of taste: **the landing contradicts the composer.** It took no
`canWrite` prop, while `OperatingModeControl` refuses Plan and Auto for a
read-only chat. So on a Review or Explain chat, three large equal-weight mode
cards offered choices as freely selectable an inch above the pills that
correctly refused them -- and clicking one lit it up while the engine would
refuse it. A control that visibly accepts a choice it cannot honour is a Rule
#1 failure, and here the *more prominent* of the two controls was the wrong
one.

That is fixed, with the rule extracted as `isModeBlocked` so the two surfaces
cannot disagree again. The framing question -- whether the landing should be
smaller -- is left open deliberately: both agents made a reasonable case, the
duplication is a preference rather than a defect, and it should be decided by
someone watching a real person use it.

Also fixed while there: the landing said "1 file(s) changed", the only place
in the app that counts files that way, on the first screen a new person
meets. `describeSource` had no tests despite producing that copy; it has
eight now.
