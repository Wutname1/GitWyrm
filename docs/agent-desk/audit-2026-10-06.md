## "The registry's registration-leak shape" was never open

It entered the list at pass 48 and has been carried about 27 times. Reading
what pass 48 actually wrote: it sits under a heading called **"Registry
concerns checked and found sound"**, and its closing sentence is

> Recorded here so it is a decision rather than an oversight.

It is a deliberate, argued decision -- no RAII guard, because `Drop` would
mean restructuring ownership for a hazard with no live instance.

Re-derived against today's code rather than trusted: three live `register()`
call sites (`agent_desk.rs`, and two in `agent_graph.rs`). Between each
`register` and its `spawn` there is nothing but infallible clones, and two of
the three carry comments explaining that the ordering is deliberate --
registration must precede the first `Working` event so a Stop landing in that
window still finds a live execution.

The claim holds. **Nothing to fix.** It is removed from "Still open" and
recorded as settled, because carrying a decision in a list of open work is
how a decision gets re-litigated by whoever reads the list next.

## "Three hand-written payloads" was two-thirds stale (`405c6a4`)

`eventPayloadContract.test.ts` fails when a screen declares its own copy of a
shape the backend already defines. Its `ROOTS` list bounds where it looks,
and its header documents the exclusions.

The header says **three**. It lists **four**, in three bullets. Reading each
against the code:

| exclusion | stated reason | actually |
|---|---|---|
| `UpdateProgress` | `u64`; specta refuses | correct, unchanged |
| `settingsSync` | no Rust counterpart | correct, unchanged |
| `AiCommitProgressPayload` | "derives `Serialize` but not `specta::Type`" | **false** -- it derives `specta::Type`, is registered in `lib.rs`, is in `bindings.ts`, and the dialog already imports it |
| `AiResolveProgress` | same bullet | **true** -- genuinely hand-written |

So the guard was switched off for one payload that had not needed it off for
some time. The exclusion outlived its reason, and because the reason was
written down as a pair, the true half kept the false half alive.

`AiResolveProgress` was the real one: `interface AiResolveProgress` declared
in `AiResolveStream.tsx`, three `String` fields, no 64-bit obstacle. It now
derives `specta::Type`, is registered beside the commit payload in `lib.rs`,
and the view imports the generated shape.

Both files are in `ROOTS`. Verified by restoring the hand-written interface
and watching the guard fail, naming the file and the type.

## What this cost, and did not

No behaviour changed. `bindings.ts` grew by one type and is additive. The
value is that a real drift guard now covers two more live event streams --
including the conflict resolver's, where a silent mismatch means a long
resolve shows no progress and reads as a hang.

## Note on method

**A carried list is a cache, and caches go stale.** The "Still open" block
has been copied forward for dozens of passes. Two entries checked, two wrong:
one had never been open, and one had been two-thirds closed by other work
that never revisited the note. Neither error was visible from the list --
only from the code.

**A stated reason is a claim with a date on it.** Pass 73 found this with a
deferred fix, pass 72 with a comment recording a fix. Here the shape is a
documented *exception*: it explained precisely why it was allowed, which is
exactly what makes it checkable -- and what makes it worth re-checking once
the code around it has moved.

**Pairing two exceptions in one sentence hid one of them.** Had the bullets
been separate, the stale one would have read as plainly false on its own.
