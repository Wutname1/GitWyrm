## Two callers, one wrong answer each (`026ca19`)

`read_results` distinguishes "no file yet" (empty list) from "damaged"
(error). Both orphan-scan callers flattened that with `unwrap_or_default()`,
and an empty list here means **there is nothing left behind on disk** -- a
claim about the world.

The two needed different fixes, because they are asked different questions:

- **The whole-store sweep** must survive one bad session; abandoning the scan
  would hide every other session's real leftovers. Pass 77 judged this
  correct and it is -- but it was *silent*, so a damaged session dropped out
  of every future sweep with nothing anywhere recording it. The skip stays; a
  `log::warn!` now names the session. That is the idiom this very file
  already uses six times, including for "could not read session" in the
  startup recovery below it.
- **The single-session command** has nothing else to carry on to. It already
  returned `Result`, so the honest answer was available and simply unused. It
  now reports that the record could not be read.

The precedent was three lines away the whole time. `inspect_worktree_on_disk`
keeps a folder it cannot open visible "so the person still gets a note about
it rather than a silently skipped record." Same file, same concern, opposite
treatment.

## A test that passed with its premise removed -- the fourth in this sequence

The sweep test wrote a damaged fixture, asserted the sweep returned empty,
then asserted the read really did fail. Replacing the fixture with a valid
file, it **still passed**: the guard sat at the end, where it could not gate
the assertion above it.

The guard is now the FIRST line. Re-falsified, and this time the test fails
with the message it was given.

Worth recording precisely, because the first falsification attempt *also*
misled me: the "valid" file I substituted omitted `sessionId`, so it was
still unreadable and the test still passed -- which looked like the fix
failing rather than the fixture being wrong. The check that settled it was
reading `ResultsFile`'s actual fields rather than assuming its shape.

## Note on method

**Close the thing the last pass named.** Two passes ago the lesson was that a
carried list goes stale; the cheapest defence is not carrying an item in the
first place. This one was one pass old and took a single sitting.

**"Skip rather than fail" is half a decision.** The other half is whether
anyone can tell it happened. A skip with a log line is a judgement; a silent
one is indistinguishable from the case where there was nothing to skip.

**A falsification can fail for its own reasons.** When reverting a fix does
not produce the expected failure, the fixture is as likely to be wrong as the
fix -- check what the parser actually requires before concluding anything.
