## A failed import could say nothing at all (`b4456da`)

Two findings from pass 59, and they are one defect seen from two ends.

`useImportExternalSession`, `useContinueImportedSessionHere` and
`useUnlinkImportedSession` defined no `onError`. Every toast lived in a
per-call `mutate(vars, { onError })` callback in `ImportPicker.tsx` — and
TanStack Query drops those if the component that passed them unmounts before
the mutation settles.

`SessionRow` is rendered straight from `scan.data`, so any refetch that
changes the list rebuilds the rows. And `useAgentImportScan` set **no
`staleTime`**, so it refetched on every window focus — while its sibling
`useAgentImportAdapters` sets two minutes with a comment about filesystem
cost. The scan is the more expensive of the two: it reads and parses every
conversation file the adapter has.

So the mechanism was complete: click Import on a large session, click away and
back, the scan refetches, the row is rebuilt, the import fails — and nothing
is reported anywhere. The action silently did not happen, which Rule #1 calls
the worse case.

Both halves fixed together, because either alone leaves it reachable:
error handling moved to the hooks (which always run), and the scan given the
same staleness its sibling already had.

**The call-site handlers were removed at the same time.** Leaving them would
have shown the same failure twice whenever the row *had* survived —
substituting one Rule #1 problem for a smaller one.

`IMPORT_SCAN_STALE_MS` is named in `agentImportDisplay.ts` rather than
inlined twice, which is also the only part of this the test setup can reach:
`vitest.config.ts` deliberately scopes tests to `src/lib`.

## A mistake worth recording

My first edit added the handler to two of the three mutations — the
replacement for `useImportExternalSession` did not match and I did not notice
until counting `onError` against `export function` afterwards. The most
important of the three was the one left out.

Nothing failed. Typecheck passed, every test passed, and the commit would
have shipped a fix that missed its own headline case. The check that caught
it was mechanical: list the mutations, list the handlers, compare. Worth
doing whenever an edit is applied by pattern rather than by hand.

recorded the missing `onError` and the missing `staleTime` as separate items,

the report still on them. The pairing was the finding.
