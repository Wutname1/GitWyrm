## Two silent no-ops in `json_patch` (`3208acc`)

Both reproduced with a probe (removed before commit) before being fixed, so
the behaviour is recorded rather than described:

```
PROBE escaped-update: {"we\"ird": 1, "b": 2,
  "we\"ird": 5}
PROBE escaped-remove: {"we\"ird": 1, "b": 2}
PROBE duplicate: {"a": 3, "a": 2}
PROBE reader-sees: 2
```

**A key was matched by its spelling, not its meaning.** `find_member_value_span`
compared the raw source text between the quotes against the path segment, so a
key the file wrote as `"we\"ird"` never matched the path `we"ird`. An update
became an insert -- leaving two copies of a key that was already there -- and
`remove_path` returned `Ok` having removed nothing. Now decoded through
`serde_json` before comparing, which is the exact inverse of the escaping
added last pass.

**With a duplicated key, the write went where nothing reads.** The scan
returned on the first match; every JSON reader takes the last. So writing to a
file with `"mcpServers"` twice put the connector in the dead first map and
reported success -- the third `PROBE` line shows the reader still seeing `2`
after a write of `3`. The scan now records the last match instead of returning
on the first.

## Codex's settings file was being rewritten wholesale (`0cecb8f`)

`toml_patch`'s header promises `toml_edit` "keeps every byte it does not
deliberately change". Two bytes it does not keep:

```
PROBE crlf-in-out-has-cr: false
PROBE bom-kept: false
```

Every CRLF became LF and a byte-order mark was dropped. Nothing is lost, but
on Windows a one-key edit shows up as a diff touching every line of a file the
person hand-writes and comments -- which makes it impossible to see what
GitWyrm actually did, and is the opposite of the trust the module doc is
claiming. `json_patch` already restores both and has a test pinning it; the
TOML side now does the same.

## A test of mine, deleted for failing to prove anything

I wrote a test asserting that a key written `"a"` is matched by the path
`a`. It passed. It also passed with the fix reverted -- and after several
attempts I could not construct a version that discriminated, because reading
the result back normalises both spellings to the same thing.

Deleted rather than kept. The escaped-quote and duplicate-key tests were each
verified to fail against their defect, so the case is covered; a third test
that cannot be shown to catch anything is worse than no test, because it reads
like a guard.

That is the second pass running a test of mine has failed this check
(pass 53's was a symlink test that silently skipped). The habit that catches
them is the same one: revert the fix, watch the test fail, and believe the
result.

## Note on method

**Probe first, then fix.** Both `json_patch` defects were reproduced as
printed output before a line was changed, and both `toml_patch` ones too. That
costs one throwaway test run and buys certainty that the thing being fixed is
the thing that was wrong -- which matters more here than usual, since three
audit claims in five passes have not survived verification.
