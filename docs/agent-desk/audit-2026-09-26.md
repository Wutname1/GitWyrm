## Two findings that dissolved on checking

Recorded because a pass that only reports what survived is not an honest
account of where the time went.

**`OperatingModeControl` -- a click that does nothing.** The mode pills use
`aria-disabled` rather than `disabled`, deliberately, so a keyboard user can
still reach them and hear why. Clicking a blocked pill is a guarded no-op, and
the `title` only shows on hover. That looked like Rule #1: a click with no
visible response.

It is not. The trailing note beside the pills renders `READ_ONLY_REASON`
whenever `canWrite` is false, so the reason is already on screen before the
click. `ProviderControl`, which has the identical shape, renders its reason
inline in the row for the same purpose. Both are fine.

**`PlanChecklist` -- truncated step text.** Plan steps render with `truncate`
and no `title`, on a checklist someone reads to decide whether to press Start.
Also not a defect: `ConversationPane` renders the full message body directly
above with `whitespace-pre-wrap`, and `displayText` does not strip the
checklist lines. The row is a summary of text already shown in full.

## An imported chat could attach to the wrong project (`9a9e032`)

`reconcile::normalize` lowercased the whole path before comparing, commented
"Windows paths are case-insensitive".

`PRODUCT.md` line 20: "GitWyrm is a Windows-first desktop Git client with
Linux support." On Linux `/home/dev/Repo` and `/home/dev/repo` are two
different directories. Folded together they compare equal, so
`resolve_project_path` returns `Resolved` and an imported chat is silently
filed under a project it has nothing to do with.

The function's own doc comment forbids exactly this: "no fuzzy/prefix
matching, since a wrong guess (matching a session to the wrong repo) is worse
than an honest `Unresolved`." Case-folding is a fuzzy match wearing a
normalizer's name.

**And the honest failure is cheap.** `Unresolved` renders "Project not found:
`<path>`" with `offerLinking: true` -- the path is shown and linking is
offered. Being conservative costs one click; being wrong costs a chat filed
under the wrong project with nothing on screen admitting it was inferred.

## Why the drive letter still folds

The obvious fix -- drop case-folding entirely -- would have broken a shipping
adapter, and checking is what caught it. VS Code records its workspace as
`file:///c%3A/code/foo`, which `file_uri_to_path` decodes to a **lowercase**
drive letter, while GitWyrm's own repo list stores `C:/code/foo`. Exact
matching would fail every Copilot import on Windows.

So the split is: fold the drive letter, compare the rest exactly. `C:` and
`c:` are the same volume on every Windows machine -- that is a property of
path *syntax*, not of how a disk was formatted, so it needs no guess.

**`cfg(target_os)` was the other candidate and lost.** It decides a property
of the *filesystem* from a property of the *build target*, and those diverge:
a Windows directory can be made case-sensitive, macOS APFS formats either way,
and the recorded path may belong to a machine this build never runs on.

**Two siblings do the same lowercasing and are both correct.**
`git::worktree::paths_equal` and `normalize_worktree_key` each try
`canonicalize()` *first* and only fall back to lowercasing when the path does
not exist. They can, because their paths are local. `reconcile` cannot -- its
doc comment says so -- which is what made it the only site claiming identity
from a string alone.

## The test that was the evidence for the bug

`backslash_paths_and_case_still_match` asserted that `c:\Code\GITWYRM` matched
`C:/code/GitWyrm`. It was the only evidence for whole-path folding, and its
input was **invented**: no adapter produces a segment whose case differs from
the real folder, and grepping every fixture confirms it. A test written to
describe behaviour, rather than from something observed, kept a real defect
alive by making it look intentional.

Rewritten to state what is now true, and to say in its own comment what it
used to assert and why that was wrong.

## Note on method

**Two dissolved findings is a normal pass, not a wasted one.** Both looked
like real Rule #1 defects from the component alone, and both were answered by
reading one level out -- the sibling that renders the same reason, the parent
that renders the same text. The check that settles a UI finding is usually
"what else is on screen at that moment", and it is cheaper than the fix.

**A background `cargo test` blocks a foreground one.** Two runs in this pass
died on `link.exe` exit code 1104 -- the test binary is held by the running
suite. Run them serially; the second is not measuring anything the first
will not.
